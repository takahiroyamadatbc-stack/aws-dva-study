# Secrets Manager クロスリージョンレプリケーション 要点

## 問題

us-west-1 のアプリケーションに us-east-1 の冗長性を追加したい。us-west-1 の Secrets Manager にあるシークレットを us-east-1 にレプリケートするための最適な方法を選ぶ問題。

正解: 「各シークレットのレプリケーションを構成し、レプリケーションリージョンとして us-east-1 を追加する。レプリケートされたシークレットの暗号化には us-east-1 の KMS キーを選択する」

## 誤答の判断基準

| 選択肢の要旨 | 判断 | 理由 |
| --- | --- | --- |
| レプリケーションルールをローテーション中に実行 | 誤り | レプリケーションはローテーションと**独立して動作**する。値が変わるたびに自動同期されるので、ローテーション時だけ実行するルールは継続的な同期を阻害する |
| Secrets Manager → S3 → S3レプリケーションで us-east-1 に転送 | 誤り | 機密情報を不必要にS3へ露出させるリスクがある。Secrets Manager自体には「ライフサイクルルール」という機能はなく、専用のレプリケーション機能で完結する |
| us-east-1に新規シークレットを手動作成し、ソースをus-west-1に指定。暗号化はus-west-1のKMSキー(選んで間違えた) | 誤り | 手動作成は運用負荷が高く、そもそも既存シークレットへの設定追加だけで足りる。またレプリカの暗号化にソース側(us-west-1)のキーを使うとリージョン間依存が生まれ、us-west-1障害時にus-east-1側も復号不能になりDRの意味がなくなる |
| 既存シークレットにレプリケーションリージョン(us-east-1)を追加し、暗号化はus-east-1のKMSキー | 正解 | ネイティブなクロスリージョンレプリケーション機能。各リージョンが独立して暗号化を管理でき、DR時の可用性が高い |

## 仕組みの整理

```
プライマリシークレット(us-west-1)
   │  値の変更(作成・更新)のたびに自動同期
   ▼
レプリカシークレット(us-east-1、読み取り専用)
   - 暗号化キーは us-east-1 の KMS キーを使う(ソース側のキーは使わない)
   - 直接の書き込み(PutSecretValue等)は不可。更新は常にプライマリ側で行う
```

- **同期のトリガーは「値の変更」のみ**: ローテーション設定の有無やタイミングとは無関係。ローテーションが値を変えれば結果的に同期されるが、レプリケーション自体をローテーションに紐づける設定項目は存在しない
- **レプリカは読み取り専用**: アプリはレプリカからシークレットを読めるが、更新・ローテーションの実行対象は常にプライマリ
- **暗号化キーはリージョンごとに独立させる**: レプリカの暗号化には必ずそのリージョン(us-east-1)のKMSキーを指定する。ソースリージョンのキーを流用すると、ソースリージョン障害時にレプリカ側も復号できずDRとして機能しなくなる
- **プライマリの削除・昇格**: プライマリを削除するとレプリカが「スタンドアロン」に昇格できる(リージョン障害時のフェイルオーバー用途)

## 押さえておくべき落とし穴

- 「レプリケーション」と聞いて「新規に別リソースを作ってソースを指定する」という一般的なDBレプリケーションやS3クロスリージョンレプリケーションのイメージを持ち込むと誤る。Secrets Managerでは**既存シークレットに設定を追加するだけ**
- 暗号化キーは直感で「元データのあるリージョン」を選びがちだが、正しくは「レプリカが存在するリージョン」
- Secrets Managerに「ライフサイクルルール」という機能は存在しない(選択肢の引っかけとして登場することがある)

## 検証の流れ(このLabのスクリプト)

1. `01_create_secret.sh`: us-west-1にプライマリシークレットを作成
2. `02_create_kms_key.sh`: us-east-1にレプリカ専用のKMSキーを作成
3. `03_add_replica.sh`: `replicate-secret-to-regions` で既存シークレットにus-east-1をレプリカリージョンとして追加
4. `04_check_replication.sh`: レプリケーション状態の確認、レプリカからの読み取り確認、レプリカへの直接書き込みが失敗すること、プライマリ更新がレプリカへ自動同期されることを確認

## 結論

Secrets Managerのクロスリージョンレプリケーションは、既存シークレットに「レプリカリージョンを追加する」だけで完結するネイティブ機能。ローテーションとは無関係に値の変更のたびに自動同期され、レプリカは読み取り専用。暗号化キーは(ソース側ではなく)レプリカが存在するリージョンのKMSキーを指定することで、リージョン間の依存をなくしDR時の可用性を確保する。
