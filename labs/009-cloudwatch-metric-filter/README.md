# 009 CloudWatch Logsメトリクスフィルターによるエラー検知通知

## 問題

新しいアプリケーションをAWSにデプロイし、アプリケーションログをAmazon CloudWatch Logsにストリーミングしている。開発チームは、ログに「ERROR」という単語が表示された場合にメールで通知を受け取る必要がある。Amazon SNSトピックを設定し、開発チームをそのトピックにサブスクライブ済み。要件を満たすために次に行うべき作業を選択する問題。

選択肢:
- CloudWatch Logs Insightsでメトリクスクエリを作成し、1以上の値でアラームを作成する
- ロググループを選択し「ERROR」を検索語としてメトリクスフィルターを作成、そのメトリクスが1以上でSNSに通知するアラームを作成する
- ロググループを選択し「ERROR」をフィルターパターンとしてSNSサブスクリプションフィルターを作成する
- フィルターパターン「ERROR」を設定し、ロググループディメンションとSNSトピック送信先を含むCloudWatchアラームを作成する

正解: 「メトリクスフィルターを作成し、そのメトリクスに対してアラームを作成する」の2段階構成。

## 選んだ答えと理由

選んだ: 「フィルターパターン『ERROR』を設定し、ロググループディメンションとSNSトピック送信先を含むCloudWatchアラームを作成する」(不正解)

理由: CloudWatchメトリクスフィルターを使った経験がなく、ログのフィルターパターンをアラームに直接設定できると誤解した。アラームがログを直接監視できるものだと思い込んでいた。

## 誤答の型

サービス構成要素の欠落: CloudWatchアラームは**メトリクス**に対してのみ設定でき、ログそのものを直接監視することはできない。「ログ→メトリクス」の変換ステップ（メトリクスフィルター）が別リソースとして必要であることを知らなかった。

## 仮説

CloudWatch Logsのアラート機構は2段構成である。

- **メトリクスフィルター**: ロググループに到着するログイベントをリアルタイムで走査し、フィルターパターンにマッチした回数（または値）をカスタムメトリクスとして記録する「ログ→メトリクス変換装置」
- **アラーム**: そのメトリクスのしきい値を監視し、超過時にSNSなどへ通知する「メトリクス→通知変換装置」

アラームはメトリクスフィルターが生成したメトリクスにしか反応できないため、フィルターパターンを直接アラームに渡す（今回選んだ誤答）ことはできないはず。また、メトリクスフィルターは**作成後に到着するログイベントにのみ**適用され、過去ログには遡って適用されないはず。

## 検証

> 実機デプロイは行っていない(標準ではコード整備までを完了条件とする方針。CLAUDE.md「AWS実行について」参照)。以下はユーザーが実行を希望した場合の検証手順として設計したもの。

1. [`01_create_resources.sh`](01_create_resources.sh): ロググループ、SNSトピック＋メールサブスクリプション、「ERROR」にマッチするメトリクスフィルター(`ErrorCount`)、`ErrorCount`のSumが1以上で1回評価したら通知するCloudWatchアラームを作成する（`NOTIFY_EMAIL=you@example.com ./01_create_resources.sh` で実行。SNS購読確認メールのリンクをクリックしないとアラーム通知は届かない点に注意）
2. [`02_generate_logs.sh`](02_generate_logs.sh): `ERROR`を含む行2件、含まない行3件を`put-log-events`で送信し、メトリクスフィルターが特定文字列だけを拾うことを確認できる状態にする
3. [`03_check_metric_and_alarm.sh`](03_check_metric_and_alarm.sh): `ErrorCount`メトリクスの値とアラームの状態(`StateValue`)を取得する

期待する結果:
- `ErrorCount`メトリクスに「ERROR行の件数(=2)」のデータポイントが記録される（INFO行はカウントされない）
- アラームが`ALARM`状態に遷移し、SNS経由でメール通知が届く
- ログ送信前に存在した過去ログはメトリクスフィルター作成後の対象外であり、カウントに含まれない

## 結論(1行)

> CloudWatchアラームはメトリクスしか監視できないため、ログ内の文字列を検知するにはまず「メトリクスフィルター」でログをカスタムメトリクスに変換する必要がある。フィルターパターンを直接アラームに渡すことはできない。
